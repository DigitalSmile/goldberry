## 1. `:media-platform` into `:media`

Done:

- Sources, tests, test fixtures and the fixture script moved into `:media` with
  their packages unchanged (`…media.platform.{bitstream,macos,linux,windows}`).
  The script is now `media/src/test/fixtures/make-platform-fixtures.sh`.
- `module-info.java` merged: `exports …media.platform`, the six
  `DecoderProvider`s and CoreAudio's `OutputLatency` under `provides`. The
  service files moved to `media/src/main/resources/META-INF/services`.
- The two native-image metadata generators became one `…media.nativeimage`
  package: `MetadataGrammar`, `PlatformDescriptors` and `MediaForeignMetadata`.
  FFmpeg's shapes come from `…media.ffi.FfmpegDescriptors`, which was
  `FfmpegForeignMetadata`. Each class has a test.
- The coverage floor counts this system's decoders only under
  `-Pgoldberry.platform.required=true`, and never another system's.
- `media.yml` runs one `:media:check` with both `required` flags. The showcase,
  `settings.gradle`, `.idea/gradle.xml`, `NOTICE` and `THIRD-PARTY-NOTICES.md`
  were updated.
- `OutputLatencyTest.installedHere` holds off macOS only. CoreAudio's provider
  is always on the path now.

The docs that describe the module were updated too (`docs/goldberry-media.md`
§5, `docs/media-plan.md`, `docs/ARCHITECTURE.md` §15, `docs/gpu-plan.md`).

Verified: `:media:check` with `-Pgoldberry.media.required=true
-Pgoldberry.platform.required=true` on linux-x64 gave 1430 tests, 0 failures and
134 skipped (other systems' decoders, VAAPI). 242 of them are the moved
platform and metadata tests, including all 49 GStreamer tests, run against the
real decoders. The coverage floor held with the Linux decoders counted.

## 2. Snapshot artifacts

- `html`, `emoji` and `gpu` were already `OPTIONAL` in `PublishedModules`. They
  were not reaching Central, though: Snapshot runs 32 and 33 failed in
  `:natives:gpuTest` on every OS, because GPU test teardowns called SDL after a
  missing library had skipped their setup. Eight teardowns now return early.
  All three `gpuTest` tasks pass without the library, and `:natives:gpuTest`
  passes with it (28 of 28, X11).
- `:media` is published, optional, with FFmpeg as `ffmpeg-<target>`
  classifiers. `publish.yml` calls `media.yml` for the builds. A release
  refuses without all four targets.
- Verified: `publishToMavenLocal` gives the jar, sources, javadoc, POM, module
  file and `ffmpeg-linux-x64` classifier. `:media:javadoc` passes doclint and
  `:build-logic:test` passes (219 tests).
- **Not verified here: a real Snapshot run.** It needs a push.
- Open before a release: FFmpeg for `windows-x64` and `linux-aarch64`, and the
  LGPL source offer.

## 5. `package-info.java` everywhere

- 122 main packages had no `package-info.java`, and 6 more had one without
  `@NullMarked`. All 128 have one now, each with a description of the
  package's role:
  - 112 new and 6 existing files are `@NullMarked`.
  - The 10 packages in build tools (`:assets`, `:weaver`, `build-logic`) are
    documented without the annotation, since those modules run no Error Prone.
- `PackageInfoTest` (build-logic) keeps it that way. It fails on a package
  with no `package-info.java`, one with no doc comment, or one in a module
  under NullAway that is not `@NullMarked`. On its first run it found the 6
  unmarked files nobody had listed.
- `tools/nullness/sweep.sh` had two bugs that made it report "clean" after one
  pass:
  - it matched `error: [NullAway]` in the very `warn` mode it runs in;
  - it compiled with Gradle's up-to-date check on, and a cached compile prints
    no warnings.
  Both are fixed.
- A third defect was in javac itself: it prints at most 100 warnings and then
  stops, silently. The conventions now raise `-Xmaxwarns` and `-Xmaxerrs` in
  `-Pgoldberry.nullaway=warn` mode. The first counts, 229 findings, were
  capped, and the real total was about 560:

  | Module | Findings | How resolved |
  | --- | --- | --- |
  | `:core` | ~154 | ~69 parameters and ~29 returns `@Nullable`, ~11 fields, 27 `requireNonNull` (13 through the new `RenderObject.appliedBox()`), 7 wrong auto-annotations corrected, `NullAway.Init` on `Launcher`'s six late fields |
  | `:natives` | 0 | runs no Error Prone; the parameters `:core` passes null to (`YogaNode.setMeasureFunction`, `SdlTray.open`/`icon`, `SdlTrayItem`, `SdlFileDialogs.show`) are `@Nullable` there now, which removed seven suppressions in `:core`. `requires transitive static org.jspecify` added |
  | `:widgets` | ~353 | the sweep took 96. Then ~150 record components that store null became `@Nullable`, `Select`, `Field`, `TextArea`, `TextInput`, `Item`, `Button` and `Toast` got canonical constructors with `@Nullable` parameters for their defaults, ~20 `requireNonNull`, ~12 local copies, and `NullAway.Init` on 2 fields |
  | `:example` | 42 | `NullAway.Init` on 13 lifecycle-set fields, 9 `@Nullable` fields, 6 `@Nullable` returns, 1 `requireNonNull` |
  | `:html` | 5 | 4 cleared by `:widgets`' signatures, 1 `requireNonNull` |
  | `:media` | 1 | cleared by `Select`'s signature; 4 `requireNonNull` where `Wiring.handle` became `@Nullable` |
  | `:gpu`, `:emoji` | 0 | `Canvas3d.inflate` got the same `requireNonNull` as `:media` |

- **One real bug was fixed:** `Accelerators.unbind(host, bound)` is documented
  as unbinding "whoever holds those keys now". It passed a null owner down,
  which the router reads as "only keys nobody owns". A null owner now removes
  the key outright. Nothing in the repository called it.
- **Four `:core` signatures documented null and did not declare it.** They are
  `@Nullable` now: `Popup.focusOn`, `Attributes.id`, `Box.painting` and
  `TraySpec.tooltip`. That removed the last suppression outside the documented
  `NullAway.Init` ones, and a `""` placeholder in `TrayIcon`. `Host.shortcut`
  and `removeShortcut` keep a non-null owner. Their contract calls the owner an
  identity token, and a null owner goes to the overload without one.
- **Public signatures now say `@Nullable`**, and each widens a contract the
  code already honoured:
  - `Host.popup(…, fit)`
  - `PointerEvent.button()`
  - `HitTest.Region.owner`/`inverse`
  - `FocusScope.roves`
  - `Box.text`/`icon`/`mark`/`painting`/`owner`
  - `Overrun.between`
  - `Attributes.key`/`tooltip`/`contextMenu`/`name`
  - `CssColor.parse`
  - `ActionRegistry.resolve`/`resolveValued` and `BindingRegistry.resolve`
  - `Named.resolve`
  - `Wiring.handle`
  - `Validator.check`
  - the bound controls' `source`/`onChange`/`binding()`
  - `Button.icon`/`onPress`
  - `Select.value`/`onQuery`
  - `Tree.onSelect`/`onCheck`
  - `ChartOptions.time`/`crosshair`
  - `TrayIcon.icon`/`tooltip`

  `Paragraph.layout` went the other way: it never returns null.
