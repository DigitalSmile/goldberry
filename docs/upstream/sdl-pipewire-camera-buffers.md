# SDL issue: PipeWire camera never streams (no `SPA_PARAM_Buffers`), so the permission stays pending (and in 3.4, `SDL_CloseCamera` hangs)

Prepared 2026-11-22 for `libsdl-org/SDL`; **not filed**. It carries **no patch**. SDL's
pull-request template asks the author to confirm that a contribution contains no code
generated by a large language model, and the patch the superbuild carries was written by
one. So the fix is described in prose here, for whoever writes the upstream change. It is likely the root cause of
[#11473](https://github.com/libsdl-org/SDL/issues/11473) and
[#9989](https://github.com/libsdl-org/SDL/issues/9989), both open, where the symptom was
seen and V4L2 was made the default instead. The text below can be a new issue or, trimmed,
a comment on #11473. Everything under the rule is the text to post.

---

**Title:** PipeWire camera: stream never reaches STREAMING because no `SPA_PARAM_Buffers` is sent (root cause of #11473 / #9989)

### Summary

With `SDL_CAMERA_DRIVER=pipewire`, cameras are listed with all their formats, but no
frame ever arrives. `SDL_GetCameraPermissionState()` stays `0` (pending) for ever.
PipeWire refuses the stream during buffer negotiation:

```
pw.stream | [stream.c: 1506 on_core_error()] 0x...: error id:4 seq:25 res:-32 (Broken pipe): error use input buffers: -22 (Invalid argument)
```

`on_stream_param_changed()` in `src/camera/pipewire/SDL_camera_pipewire.c` is empty.
When the format is negotiated, the stream never answers it with an `SPA_PARAM_Buffers`
param, and PipeWire's V4L2 source rejects the default buffers. So the stream never
reaches `PW_STREAM_STATE_STREAMING`, which is the only place the driver calls
`SDL_CameraPermissionOutcome(device, true)`. PipeWire's own `video-capture.c` example,
and GStreamer's `pipewiresrc`, send this param, and `pipewiresrc` streams the same camera
fine:

```
gst-launch-1.0 pipewiresrc target-object="C922 Pro Stream Webcam (V4L2)" num-buffers=20 \
    ! "video/x-raw,format=YUY2,width=640,height=480" ! fakesink      # works
```

In 3.4.18 the app then also hangs in `SDL_CloseCamera()`: `WaitDevice` used an untimed
`pw_thread_loop_wait()` that nothing ever signals. `main` already fixes that part
(660c4acf, "Don't block forever in WaitDevice if no signal arrives").

### Environment

- SDL `main` at c8da1796 (2026-11-21), and 3.4.18 (`release-3.4.18`, 829a65d7). Both are
  static, with PipeWire loaded dynamically (`libpipewire-0.3.so.0`).
- PipeWire 1.6.2, WirePlumber 0.5.13, Ubuntu 26.04.1, kernel 7.0.0
- Logitech C922 Pro Stream Webcam (046d:085c, uvcvideo), exposed by WirePlumber's V4L2
  monitor as node `C922 Pro Stream Webcam (V4L2)`

### Reproduce

<details><summary><code>repro.c</code>: open the first camera, wait 5 s for a frame, close</summary>

```c
/* SDL_CAMERA_DRIVER=pipewire ./repro : opens the first camera, waits for
 * permission and a frame, then closes it, printing how long each step took. */
#include <SDL3/SDL.h>
#include <stdio.h>

static double now(void) { return (double)SDL_GetTicksNS() / 1e9; }

int main(void)
{
    if (!SDL_Init(SDL_INIT_CAMERA)) { printf("SDL_Init: %s\n", SDL_GetError()); return 1; }
    printf("driver: %s\n", SDL_GetCurrentCameraDriver());
    int count = 0;
    SDL_CameraID *ids = SDL_GetCameras(&count);
    if (count == 0) { printf("no camera\n"); return 1; }
    printf("camera: %s\n", SDL_GetCameraName(ids[0]));
    SDL_CameraSpec spec = { SDL_PIXELFORMAT_YUY2, SDL_COLORSPACE_UNKNOWN, 640, 480, 30, 1 };
    double t0 = now();
    SDL_Camera *camera = SDL_OpenCamera(ids[0], &spec);
    if (!camera) { printf("SDL_OpenCamera: %s\n", SDL_GetError()); return 1; }
    int frames = 0;
    while (now() - t0 < 5.0 && frames < 30) {
        SDL_PumpEvents();
        if (SDL_GetCameraPermissionState(camera) == SDL_CAMERA_PERMISSION_STATE_APPROVED) {
            Uint64 ts;
            SDL_Surface *frame = SDL_AcquireCameraFrame(camera, &ts);
            if (frame) {
                if (frames == 0) printf("first frame after %.2f s\n", now() - t0);
                frames++;
                SDL_ReleaseCameraFrame(camera, frame);
                continue;
            }
        }
        SDL_Delay(5);
    }
    printf("after %.2f s: permission %d, %d frames\n", now() - t0, (int)SDL_GetCameraPermissionState(camera), frames);
    double t1 = now();
    printf("closing...\n");
    fflush(stdout);
    SDL_CloseCamera(camera);
    printf("closed in %.2f s\n", now() - t1);
    SDL_free(ids);
    SDL_Quit();
    return 0;
}
```

</details>

```
gcc -o repro repro.c -I<sdl>/include <sdl-build>/libSDL3.a -lm -ldl -lpthread
SDL_CAMERA_DRIVER=pipewire ./repro
```

Output on `main` (c8da1796):

```
driver: pipewire
camera: C922 Pro Stream Webcam (V4L2)
after 5.00 s: permission 0, 0 frames
closing...
closed in 0.10 s
```

On 3.4.18 the output is the same, except that `SDL_CloseCamera()` never returns. The
process also ignores SIGTERM there, because SDL's handler only queues `SDL_EVENT_QUIT`.
The same binary with `SDL_CAMERA_DRIVER=v4l2`, which `main` now picks by default,
works:

```
driver: v4l2
camera: C922 Pro Stream Webcam
first frame after 0.26 s
after 1.22 s: permission 1, 30 frames
closing...
closed in 0.08 s
```

### What fixes it

In `on_stream_param_changed()`, when `id == SPA_PARAM_Format` and `param` is not NULL,
answer with `pw_stream_update_params()` and one `SPA_PARAM_Buffers` object, as
PipeWire's `src/examples/video-capture.c` does. That example also sets size and stride
from the parsed format. Here they could be left to the source: a range of buffers (2 to
16), one block each, and a `dataType` of `MemPtr | MemFd`, so the memory stays mappable
under `PW_STREAM_FLAG_MAP_BUFFERS`. `pw_stream_update_params` would join the driver's list
of symbols loaded at run time. It has been in PipeWire since 0.3, so the 0.3.44 floor
holds.

A local change along those lines, on 3.4.18 together with the timed wait `main` already
has, gives on PipeWire:

```
driver: pipewire
camera: C922 Pro Stream Webcam (V4L2)
first frame after 0.05 s
after 1.02 s: permission 1, 30 frames
closing...
closed in 0.04 s
```

and the camera streams through PipeWire in every mode tried:

| Mode | Rate |
|---|---|
| 640×480 NV12 (converted from YUY2) | 30.1 fps |
| 1280×720 YUY2 | 9.9 fps |
| 1280×720 MJPG | 30.0 fps |
| 1920×1080 MJPG | 30.0 fps |

### A second thing, from reading the code (not observed)

`on_stream_state_changed()` runs on PipeWire's thread loop with the loop lock held, and
`SDL_CameraPermissionOutcome()` takes the device lock. `SDL_CameraThreadIterate()` holds
the device lock while `PIPEWIRECAMERA_AcquireFrame()` takes the loop lock. Once the camera
is approved, a stream that went back to `STREAMING` (after a pause or a renegotiation)
would take the two locks in the opposite order and could deadlock. Calling
`SDL_CameraPermissionOutcome()` only while the permission is still pending would avoid
it. The only writer that can move the permission from pending is this callback, so an
unlocked check is enough.

With this fixed, the comment in #11473 ("we're just going to favor v4l2 over pipewire")
might be revisited. PipeWire is the only way to reach libcamera-only laptop cameras, and
the only way for two applications to share a camera.
