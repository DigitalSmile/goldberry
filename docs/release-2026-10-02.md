# The first Release run, `v2026.2`

Working notes for 2026-10-02. The tag `v2026.2` on 190569a5 started Release run
36985188261, the first run of `release.yml` on a tag. It went red in one test on
one lane, and `maven` waits for every lane, so nothing was uploaded (§1, §2).
Re-run, it uploaded, and Central refused all ten POMs for a missing description
(§3). Nothing is on Central. The `notes` job had already opened the draft GitHub
Release, and that job edits a draft that already exists, so running it again is
safe. No ADR: both fixes repair what was meant, and decide nothing new.

## 4. Getting the release out

The tagged commit has the eager description in its build logic, so re-running
jobs on `v2026.2` would upload the same POMs and fail the same way. Nothing is
on Central: a deployment that fails validation is never published, and 2026.2
can still be released under that number.

1. Drop the failed deployment in the Portal (Deployments).
2. Turn on "Allow GitHub Actions to create and approve pull requests".
3. Delete the `bump/2026.3` branch. The bump job creates it from master again,
   and `--force-with-lease` with no remote-tracking ref to compare against
   refuses to overwrite one that exists.
4. Move the tag to master once it has the fix (`git tag -fa v2026.2`, then
   `git push -f origin v2026.2`). The release runs from the beginning, and the
   draft GitHub Release is edited rather than created again.
