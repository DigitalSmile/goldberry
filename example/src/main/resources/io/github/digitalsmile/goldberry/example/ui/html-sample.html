An HTML sample

Everything here is live. Type in the pane on the left and this side is the next frame: the editor writes one property and html-view follows it, which is all bind= means.

There is no engine under this. The page is parsed into a tree of records and folded into column, row, text and button — the same widgets every control in this window is made of, under the same cascade. litehtml is what would buy real inline layout, and it is still waiting on a wider native paint surface.

Text, and what marks it

Prose with emphasis, strength, a change of mind, a second thought, a highlight, an aside and inline code. Emphasis leans because the toolkit ships two upright faces, so it is a faux oblique rather than an italic — html.css says so in a comment you can override.

Entities are resolved on the way in — AT&T, © 2026, an em—dash and a non breaking space — so the model holds characters a reader can read. A bare ampersand is one too: Q&A, and 3 < 4.

Links, images, and what the application decides

An anchor is a button here: it takes a Tab stop, it hovers, and Space or Enter activates it. Press one and the line under this pane says what it was handed — because following a link is the application's decision and never the toolkit's. Nothing here opens a browser, resolves a relative path or fetches anything.

A Markdown link is now one widget too, for the same reason: a link's whole run becomes a single button.link rather than four hover targets.

An image is drawn when the application says where it is — images= names an ImageSource, and what a src means is the application's:

Lists

A list an author did not close, which is how most of them are written:

Numbered, and starting where it says rather than at one:

Nested, because a list holds blocks and a block can be a list:

  • The Shire
    • Hobbiton
    • Bywater
  • Bree

    2. The road east
